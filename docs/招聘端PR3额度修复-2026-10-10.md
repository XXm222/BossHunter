# PR #3 自动回复额度修复

审查意见：[点击发送前取消却永久扣除自动回复额度](https://github.com/XXm222/BossHunter/pull/3#discussion_r4235846753)。该 PR 的审查记录中有这一项具体代码问题。

## 修复

- `claim(auto=True)` 在 SQLite 写事务中检查已确认发送次数与占用次数，建立独立 reservation；不再直接增加“已发送”。
- 已确认发送时，在同一个事务里把 reservation 提交为发送次数；重复处理同一回执不会重复计数。
- 发送前因 worker 停止、会话关闭自动发送、共享冷却等原因明确取消时释放 reservation。
- 发送结果不确定或进程中断时保留 reservation，继续阻止重复外发。人工核实“已发送”提交计数，“未发送”释放。
- 跨日核实按原 reservation 的日期结算，避免把昨天的尝试扣到今天。人工手动回复不占自动回复额度。
- API 分别提供 `sent_today` 与 `reserved_today`。

旧版本没有按动作记录自动额度归属，无法可靠区分旧计数中哪些已发、哪些仅提前扣除。迁移保留历史计数，不猜测返还；新记录按 reservation 正确结算。

## 验证与生效

新增 9 项测试，覆盖上述取消场景、确认计数幂等、跨实例上限、人工核实、崩溃恢复、跨日及历史迁移。与 WS 改动一起回归：Python 545 项通过（另有 46 个 subtest），前端 82 项和 Node WS 12 项通过，生产构建通过。

真机验收未执行，没有向 GitHub 发评论或推送改动。
