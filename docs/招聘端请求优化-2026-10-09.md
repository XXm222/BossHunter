# 招聘端请求优化（2026-10-09）

## 复用监测刚完成的同步

监测生成回复时，如果本线程刚完成目标会话同步、快照哈希仍一致且读取完成不超过 30 秒，生成前复用这份快照，省去一次重复会话读取。30 秒只用于限制本地复用范围，不是平台限流阈值。若简历处理或等待锁耗时过长、会话变化、目标不同或手动单独生成，则仍执行生成前同步。

模型生成后继续重新同步并核对上下文，发送前继续读取消息、核对当前对话与编辑框、核实招聘账号。生成后与发送前的读取强制新发起，不与其他在途读取合并。人工接管、停止联系、岗位控制、草稿过期与发送结果核验保持原有规则。

## 推荐页拒绝触发共享暂停

在刷新、切换岗位、读取候选卡片与点击招呼期间，临时监听绑定推荐页的响应。BOSS 业务接口及推荐页/iframe 文档的明确 403/429、已知账号验证跳转，以及操作中明确的账号身份异常会接入现有共享暂停：关闭消息监测、停止主动招呼、保存至少 30 分钟冷却，尊重更长 Retry-After。点击后未确认的结果仍保留待核实，不自动重试。

监听不新增平台请求，并在操作结束时移除。外部域名、静态资源失败、普通 iframe 加载错误不会被推断成账号封禁。未对未知业务错误码猜测含义，也不承诺覆盖浏览器断开连接期间发生的后台响应。

## 合并相同的在途会话读取

新增 SQLite read_flights 表，Web 与 worker 使用同一数据库时可共享正在进行的会话读取。共享键包含会话、姓名、岗位、招聘账号、消息游标、附件选项及配置的浏览器身份。只有参数相同且首个读取仍在运行的调用才等待同一结果；已完成的结果不用于下一次独立读取。

结果包括正常快照、无新消息及失败。等待方取消不会取消首个读取；首个进程退出时等待方报错，不自动补发请求。下一次显式读取可清理失效占用。已完成记录超过一天后在后续读取时清理。数据库仍为本地隐私数据，不提交仓库。

HTTP 读取移到服务锁外，允许同一服务的并发同步加入在途请求；导入快照与简历处理仍在锁内，保留追加合并，晚返回的旧读取不删除新消息。

使用 conda 环境及合成数据库、浏览器响应和消息，包含两个真实本地进程共享读取、同服务并发同步、不同游标隔离、失败传播、取消、进程退出、过期快照不得复用、生成后强制新读取、推荐页拒绝触发全局暂停与普通加载错误不误暂停。未操作真实 BOSS 页面、未调用真实模型、未发送消息。

部署需同时重启 Web 与 worker，使两端都使用新的共享读取表和逻辑。节流参数、每日预算与每岗每轮 5 人配置保持不变。

## 补齐安全检查和缓存限制页信号

用户提供实际记录：首页带 _security_check 参数的 302，以及 /web/passport/zp/403.html?code=32 的 304。不能用 HTTP 304 判断限制解除，也未确认 code=32 的具体封禁含义。把这些已知地址作为需人工核实的暂停信号，无论页面来自服务器还是缓存；后台 HTTP 指向这些地址的重定向同样接入共享冷却。绑定推荐标签页已停在限制页时，暂停而不切换到其他推荐页。外部域名和无关路径不会因同名参数被认定为 BOSS 安全页。新增 4 项回归，招聘端 322 项通过；未访问或复现真实安全检查地址。
