# 招聘端审查清单修复

依据桌面《招聘端代码审查问题清单.md》核对，仅处理招聘端。用户确认：每日共用预算 100 次；同一操作内分页及联系人滚动间隔 15–30 秒；操作开始之间间隔 120–180 秒；支持一次加载更多联系人。

## 逐项结论

1. **分页耗时：已修复。** 首页使用操作间隔，后续页使用短间隔。每页仍计入预算，并检查停止、共享冷却与预算。SQLite 原子门控保存两个截止时间，Web/worker/重启后共用；后续页不会重置操作间隔，也不能绕过共享短间隔。合成时钟验证：3 页读取等待合计 30 秒，随后新操作等到首操作开始后的第 120 秒。
2. **联系人滚动上限过低：已修复。** 最多 200 次，连续 3 次没有新增联系人停止。每批累计去重，以保留已离开 DOM 的联系人。联系人读取用浏览器自动化读取 DOM 与滚动触发懒加载；HTTP friend 接口仅补充岗位归属。滚动动作进入共用预算，不能当作精确 HTTP 请求数，界面已分别显示两类统计。模拟 950 个联系人、每批 50 个，22 次滚动后稳定停止。页面可加载列表不证明覆盖全账号历史联系人；预算与停止检查仍可能提前中止加载。
3. **状态查询 N+1：已修复。** 使用一次数据库读事务批量读取，内存映射选择当前简历与有效评分；模型依据只解析一次。单个和 951 个联系人下数据库连接次数一致。保留评分指纹、简历选择失效回退及模型变更后旧评分失效规则；不输出密钥或内部 settings。
4. **Cookie 类型：未确认原清单所称错误。** LocalBossSession 的 CookieJar 返回 Cookie 对象，用属性访问；patchright BrowserContext.cookies 返回字典列表，现有字典访问符合其本地依赖类型定义。不做无依据的类型转换。
5. **发送前消息重复合并：已修复。** 移除 execute 内的提前合并，仅保留 Store.import_conversation 的事务内合并。合成并发测试验证：读取期间入库的新消息与附件不丢失，新消息使旧草稿被拒绝，无浏览器发送点击。
6. **重新开启监测未清空错误计数：已修复。** 每次开启生成新的运行标识，worker 识别后重置计数。即使 worker 未观察到短暂关闭，也能识别新运行；旧运行迟到的错误不得暂停新运行，数据库事务内核对运行标识。

配置文件、配置模板与代码默认值已同步。HTTP 消息轮询和 600 秒监测间隔保留，没有实现二进制 chatws，没有自动切换会话。

## 新消息自动外发等待排查

真机只读核对发现：今日预算用量达到 100，新消息已被其他同步操作保存，但 reply_work 未登记、没有草稿。修复为已确认会话的新候选人问题与回复任务在同一 SQLite 事务持久化；不依赖 worker 是否观察到本轮快照变化。绑定历史、未确认会话及相同消息不补建任务，模型需人工处理的同一输入仍保持原有禁止重复调用规则。

用户授权当天上限临时提高到 120。使用 request_daily_override 日期限定设置，次日回到 config 的 100，不清空已用量、不改变间隔。实际今日已用 100 次被保留。确认当前候选人最后一条平台消息时间晚于明确绑定时间、已开启自动外发且没有既有回复任务或发件箱记录后，恢复这条遗漏任务；没有调用平台或发送消息。需重启 Web/worker 使用新的消息任务登记和当日上限读取逻辑。

相关 63 项测试通过；完整招聘后端回归 285 项通过。新增手动同步后重启继续处理、相同历史及未绑定联系人不入队、当日预算覆盖跨日失效且不清零用量的测试。

## 人工接管后保留只读同步

用户确认人工接管的作用是停止大模型生成内容。轮询范围与模型处理范围已拆开：已确认绑定、岗位已勾选且允许同步的人工接管会话仍进入 HTTP 轮询，可读取收到的简历，模型评分、回复生成和自动外发暂停。停止联系、未勾选岗位、未确认绑定以及岗位暂停的限制保持原有规则。

显式模型评分也被接管守卫阻止，前端评分按钮禁用；人工编写普通回复仍可保存、确认发送。模型开始前和结果落库前再次核对接管状态；已发出的模型请求可能无法立即中止，返回结果不保存、不发送。前端进度明确显示接管后继续同步及暂停模型的范围，监测统计包含可同步的接管会话。

新增接管后消息同步而模型/自动发送不运行、简历读取但不评分、模型调用期间接管丢弃结果、人工草稿仍可保存、停止联系仍排除同步，以及前端评分禁用的回归。原测试中‘接管不得读取简历’断言按用户新规则调整，岗位暂停仍不读取。招聘后端 292 项、前端 76 项通过，生产构建通过。需重启 Web 与 worker，未调用真实平台或真实模型。

## 主动招呼 1–2 分钟与额度 10 分钟

用户确认主动招呼间隔 60–120 秒、额度有效期 600 秒。代码默认值、config.example.yaml 与本地 config.yaml 已同步；前端有效期文案改为 10 分钟。HTTP 独立读取仍为 120–180 秒，推荐页加载及岗位切换使用共用 15–30 秒加载门控。主动招呼采用持久化、跨进程共用的 request_greeting_next_at，保留全局短间隔、当日共用预算、取消和拒绝冷却；不再叠加真实浏览器流程中的 PageThrottle 循环等待。

## 刷新推荐页后 iframe 等待

刷新失败发生在重新选择岗位之前，失败时会结束本轮，不会使用默认岗位继续招呼。发现等待循环使用 Python time.sleep，无法在等待期间驱动同步 Playwright 的 iframe 挂载/导航事件；改用 page.wait_for_timeout，让 page.frames 能反映刷新后新加载的 iframe。仍保持原有超时与失败停止行为，不追加刷新、不切换标签页。

增加刷新后 iframe 延迟挂载的回归测试。只读查看当前 Chrome 页面和 iframe 地址时，推荐页 iframe 存在且符合路径条件；这一观察不能证明历史报错没有其他加载失败原因。没有刷新真实页面、切换岗位或发送消息。

本次修复后招聘后端 298 项回归通过；前端仍为 78 项及生产构建通过。需重启 Web/worker 生效。
