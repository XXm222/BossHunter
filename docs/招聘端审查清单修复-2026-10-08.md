# 招聘端审查清单修复

依据桌面《招聘端代码审查问题清单.md》核对，仅处理招聘端。用户确认：每日共用预算 100 次；同一操作内分页及联系人滚动间隔 15–30 秒；操作开始之间间隔 120–180 秒；支持一次加载更多联系人。

## 逐项结论

1. **分页耗时：已修复。** 首页使用操作间隔，后续页使用短间隔。每页仍计入预算，并检查停止、共享冷却与预算。SQLite 原子门控保存两个截止时间，Web/worker/重启后共用；后续页不会重置操作间隔，也不能绕过共享短间隔。合成时钟验证：3 页读取等待合计 30 秒，随后新操作等到首操作开始后的第 120 秒。
2. **联系人滚动上限过低：已修复。** 最多 200 次，连续 3 次没有新增联系人停止。每批累计去重，以保留已离开 DOM 的联系人。联系人读取用浏览器自动化读取 DOM 与滚动触发懒加载；HTTP friend 接口仅补充岗位归属。滚动动作进入共用预算，不能当作精确 HTTP 请求数，界面已分别显示两类统计。模拟 950 个联系人、每批 50 个，22 次滚动后稳定停止。页面可加载列表不证明覆盖全账号历史联系人；预算与停止检查仍可能提前中止加载。
3. **状态查询 N+1：已修复。** 使用一次数据库读事务批量读取，内存映射选择当前简历与有效评分；模型依据只解析一次。单个和 951 个联系人下数据库连接次数一致。保留评分指纹、简历选择失效回退及模型变更后旧评分失效规则；不输出密钥或内部 settings。
4. **Cookie 类型：未确认原清单所称错误。** LocalBossSession 的 CookieJar 返回 Cookie 对象，用属性访问；patchright BrowserContext.cookies 返回字典列表，现有字典访问符合其本地依赖类型定义。不做无依据的类型转换。
5. **发送前消息重复合并：已修复。** 移除 execute 内的提前合并，仅保留 Store.import_conversation 的事务内合并。合成并发测试验证：读取期间入库的新消息与附件不丢失，新消息使旧草稿被拒绝，无浏览器发送点击。
6. **重新开启监测未清空错误计数：已修复。** 每次开启生成新的运行标识，worker 识别后重置计数。即使 worker 未观察到短暂关闭，也能识别新运行；旧运行迟到的错误不得暂停新运行，数据库事务内核对运行标识。

配置文件、配置模板与代码默认值已同步。HTTP 消息轮询和 600 秒监测间隔保留，没有实现二进制 chatws，没有自动切换会话。

## 验证

使用 conda bosshunter 环境、临时数据库、合成平台数据与时钟，招聘后端 277 项通过，前端 68 项通过，生产构建通过。原 Dashboard 的大于 500 kB 构建提示仍存在。配置相关回归单独执行。

逐项修复期间也分别运行状态、监测、消息合并、分页与浏览器加载相关测试。未调用真实 BOSS 或真实模型，未发送真实消息；真机验收依用户要求后续统一进行。此次参数为用户确认的试运行参数，没有已验证的防封号阈值。

启动时缓存配置的 Web 与 worker 需重启；重启不会清空今日预算、共享截止时间或平台拒绝冷却。本地 config.yaml 为忽略文件，仓库使用 config.example.yaml。
